# 一次学多门语言：正确姿势与错误姿势

> 同一个任务（读 n 个数 → 输出 个数/总和/最大/最小/去重升序），三种语言各写一遍。
> 三个源文件就在本目录：`arr.c`、`arr.cpp`、`arr.py`，三者输出逐字节相同。

## 为什么"一次学多门"大多数人学崩了

他们做的是**并行学**：周一 C、周二 C++、周三 Python，各刷各的教程。
结果三份知识互不相连，忘得比学得快，而且哪门都写不出超过 50 行的程序。

正确的做法是**串行锚定 + 横向对照**：

- **一主两辅**：同一时间只有一门是"主线"（你现在是 C/C++），其余语言只在它需要的时候出场。
- **同一任务重写**：不是学三门语言，是**用三种方式解决同一个问题**。上面的 arr.* 就是这个模式。
- **对照表驱动**：每学一个概念，填一行"这个概念在三种语言里分别长什么样"。填不出来的格子 = 下周的洞。

## 三种模式的取舍

| 模式 | 做法 | 适合 | 陷阱 |
|---|---|---|---|
| 并行学 | 三门课同时上 | ❌ 别用 | 知识碎片化，哪门都浅 |
| 串行学 | 学完 C 再学 C++ 再学 Python | 打基础期 | 慢，且学第二门时无从比较 |
| **锚定 + 对照** | 一门主线，同任务多语言重写 | ✅ 你现在 | 需要主动设计"同一个问题" |

## 硬规矩（照做就不会跑偏）

1. **主线只能有一条**。周记里写清楚"本周主线 = C"，其余语言算练习。
2. **一个概念必须至少跨两门语言验证过才算学会**。例：指针 / 引用 / 对象引用 —— 三个东西名字不同，本质是"怎么指到别人"。
3. **对照表每周填 3 行就够**，别一次填完。填满 30 行时你就有了自己的语言观。
4. **项目只开一个**。想做的另外两个写进 `TODO.md` 排队，不要同时开。
5. **每周至少一次 `git commit`**。语言会忘，提交记录不会。

## 从 arr.c / arr.cpp / arr.py 能直接看出的三组差异

### 1. 内存：谁负责？
- C：`realloc` 扩容 + `free` 收尾，**两个变量**（len / cap）都得自己记。
- C++：`vector` 管容量，析构函数管释放。你只写 `push_back`。
- Python：`list` 全自动，连 len 都是 `len(nums)` 现算。

→ **同一条"动态数组"的思想，三种抽象层级。** 看懂这个，你就懂了什么叫"零成本抽象"（C++ 比 Python 快，只是因为那些活编译器替你做了，不是魔法）。

### 2. 排序：改自己还是返回新的？
- C：`qsort` 原地改（我手写插入排序是为了看清逻辑）
- C++：`std::sort` **原地**改
- Python：`sorted(x)` 返回**新列表**，`x.sort()` 才原地

→ 这是新手最容易错的一类 bug：以为排序了，其实拿到的是新对象；或者以为没变，其实原数据被改了。

### 3. 去重：谁保证"相邻"这个前提？
- C：排序后 `if (data[i] == data[i-1]) continue`
- C++：`std::unique` **只搬移不删除**，必须配合 `erase`
- Python：`set()` 一把梭，但**丢失顺序**，所以得 `sorted(set(nums))`

→ `std::unique` 不删元素这件事，坑过无数人。Python 的 `set` 丢顺序同理。

## 我在这三个文件里踩到的真 bug（留作教材）

写 `arr.cpp` 时我先把 `minmax_element` 的迭代器存下来，然后 `sort`，最后才解引用 `*mx_it` 打印。
结果输出 `max = 5 / min = 9` —— **完全错**。

原因：迭代器指向的是**位置**，`sort` 把元素搬来搬去之后，原位置上的值已经不是原来那个数了。
修法：在 `sort` 之前先把 `*mn`、`*mx` 提成 `const int` 值。

这就是"三门语言对照"最大的收益：**在 C 里你手写循环不会踩这个坑，在 Python 里 `max()` 一次性取值也不会踩。只有在 C++ 里、只有你真的动手写，才会遇到"迭代器失效"这个语言独有的概念。** 光看教程永远学不到。
